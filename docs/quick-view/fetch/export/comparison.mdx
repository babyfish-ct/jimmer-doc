The comparison is as below:  

<table>
  <thead>
    <tr>
      <th></th>
      <th>Return Entities Directly</th>
      <th>Use DTO Language</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Similarities</td>
      <td colSpan={2}>
        <ul>
          <li>
            Both can present DTO type definitions for the return type of each API to client developers
          </li>
          <li>
            Both can generate online OpenApi docs and TypeScript RPC code
          </li>
          <li>
            Both can show information in code comments to clients
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>Differences</td>
      <td>
        <ul>
          <li>
            Directly return entities <b>(Easy)</b>
          </li>
          <li>
            Need <code>@FetchBy</code> annotation in RestController to supplement type info for entity types
          </li>
          <li>
            More oriented to external API exposure
          </li>
        </ul>
      </td>
      <td>
        <ul>
          <li>
            Need to use DTO language to quickly generate DTO types
          </li>
          <li>
            Directly develop RestController based on the generated DTO types <b>(Easy)</b>
          </li>
          <li>
            Both external exposure and internal use are applicable
          </li>
        </ul>
      </td>
    </tr>
  </tbody>
</table>
